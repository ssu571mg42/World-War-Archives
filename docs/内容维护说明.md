# World War Archives - 内容维护说明（业界做法）

本项目的**内容源**采用业界常见方式：**以 JSON 为唯一数据源**，App 运行时只读这些文件，不依赖数据库或网络。

---

## 一、数据源是什么

| 角色 | 路径 | 说明 |
|------|------|------|
| **内容源（Source of Truth）** | `World War Archives/Data/*.json` | 战役、战斗、事件、地标、士兵故事及详情数据。**日常增删改只动这些 JSON。** |
| 参考 / 历史 | 项目根目录 `supabase_*.sql` | 曾用于从数据库导出；保留作备份或一次性迁移。新内容不必再写 SQL。 |

App 打包时会把 `Data/` 下 JSON 打进 Bundle，无需 Postgres、Supabase 或构建时跑 SQL。

---

## 二、日常维护：只改 JSON

- **新增或修改一条战役、战斗、事件、地标、士兵故事**  
  编辑 `World War Archives/Data/archives.json` 里对应数组（`campaigns`、`battles`、`events`、`landmarks`、`soldierStories`）。字段名用 **snake_case**，UUID 小写带连字符，日期 `YYYY-MM-DD`。格式细节见 [重新添加内容说明.md](重新添加内容说明.md) 第二节。

- **新增或修改战斗详情（部队、装备、图片、时间线）**  
  编辑 `World War Archives/Data/` 下对应文件：`battle_units.json`、`battle_unit_equipment.json`、`battle_images.json`、`battle_timeline_events.json`。注意 `battle_id`、`battle_unit_id` 等与 `archives.json` 或其它 JSON 中的 `id` 一致。

- **坦克 / 飞机型号、单位主数据、单位历史事件**  
  分别编辑 `tank_models.json`、`aircraft_models.json`、`units.json`、`unit_history_events.json`。

编辑后保存，在 Xcode 中重新编译运行即可，**不需要执行任何 SQL 或脚本**。

---

## 三、多语言字段（中 / 英 / 日 / 德）

JSON 中已支持四语言列（若之前从带四语言迁移的库导出过）。每条记录可包含例如：

- `name_zh` / `name_en` / `name_ja` / `name_de`
- `summary_zh` / `summary_en` / `summary_ja` / `summary_de`

App 会按当前语言与回退规则选用。新增或修改内容时，按需补全 `_ja`、`_de` 即可。

---

## 四、何时还用 SQL / 脚本

- **一次性从旧库或旧 SQL 迁移**：若你有一份只存在于 Postgres 或项目 SQL 里的数据，可先按 [从SQL生成JSON说明.md](从SQL生成JSON说明.md) 或 [重新添加内容说明.md](重新添加内容说明.md) 导出到 `Data/`，之后就以 JSON 为准，不必再跑 SQL。
- **批量重算 / 大改**：若希望用脚本从别的格式（如 CSV、表格）生成或校验 JSON，可以单独写小工具，读写的仍是 `Data/*.json`。

不打算再维护 SQL 时，可把根目录下 `supabase_*.sql` 视为**归档**，仅作参考或备份；新内容只维护 JSON。

---

## 五、小结

| 做法 | 说明 |
|------|------|
| **内容源** | `World War Archives/Data/*.json` |
| **日常操作** | 直接编辑上述 JSON，保存后重新编译运行 |
| **SQL** | 仅用于一次性迁移或历史参考，非日常内容源 |
| **格式与字段** | 见 [重新添加内容说明.md](重新添加内容说明.md) 第二节 |

这样与常见离线/静态数据应用一致：**数据即文件，文件即数据源。**
