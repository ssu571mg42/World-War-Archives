# 重新添加内容说明

应用已改为从 **App Bundle 内的 JSON** 加载数据，不再连接 Supabase。按下面步骤即可重新把战役、事件、战斗、故事、纪念处等内容加回应用。

**中长期内容维护**：以 JSON 为唯一数据源、日常只改 JSON 的说明见 [内容维护说明.md](内容维护说明.md)。

---

## 一、文件放在哪里

所有 JSON 都放在工程的 **`World War Archives/Data/`** 目录下，并确保在 Xcode 中勾选 **Target → Build Phases → Copy Bundle Resources**，把 `Data` 或其中的文件加入，这样才会打进安装包。

| 文件 | 必需 | 说明 |
|------|------|------|
| **archives.json** | 是 | 主列表：战役、战斗、事件、纪念处、士兵故事 |
| battle_units.json | 否 | 战斗参战单位，无则战斗详情「部队」为空 |
| battle_unit_equipment.json | 否 | 单位装备，无则「装备」为空 |
| battle_images.json | 否 | 战斗图片 |
| battle_timeline_events.json | 否 | 战斗时间线 |
| tank_models.json | 否 | 坦克型号（全局） |
| aircraft_models.json | 否 | 飞机型号（全局） |
| units.json | 否 | 单位主数据，无则点单位无法进详情 |
| unit_history_events.json | 否 | 单位历史事件 |

---

## 二、JSON 格式要求

- **字段名**：与数据库列名一致，使用 **snake_case**（如 `name_zh`、`campaign_id`、`start_date`）。
- **UUID**：字符串形式，小写带连字符，例如 `"a1b2c3d4-e5f6-7890-abcd-ef1234567890"`。
- **日期**：字符串，推荐 `YYYY-MM-DD`，如 `"1944-06-06"`。
- **空值**：用 `null`，不要省略字段（或保证 Swift 端对应属性为可选）。

### 1. archives.json（主列表，必需）

顶层是五个数组，键名固定：

```json
{
  "campaigns": [ ... ],
  "battles": [ ... ],
  "events": [ ... ],
  "landmarks": [ ... ],
  "soldierStories": [ ... ]
}
```

每条记录字段对应关系（snake_case → 用途）：

- **campaigns**：`id`, `name_zh`, `name_en`, `start_date`, `end_date`, `theater`, `summary_zh`, `summary_en`, `created_at`
- **battles**：`id`, `name_zh`, `name_en`, `start_date`, `end_date`, `latitude`, `longitude`, `campaign_id`, `theater`, `summary_zh`, `summary_en`, `sides_zh`, `sides_en`, `outcome_zh`, `outcome_en`, `created_at`
- **events**：`id`, `name_zh`, `name_en`, `date`, `latitude`, `longitude`, `campaign_id`, `event_kind`, `theater`, `summary_zh`, `summary_en`, `created_at`
- **landmarks**：`id`, `name_zh`, `name_en`, `latitude`, `longitude`, `landmark_type`, `theater`, `summary_zh`, `summary_en`, `created_at`
- **soldierStories**：`id`, `title_zh`, `title_en`, `summary_zh`, `summary_en`, `body_zh`, `body_en`, `latitude`, `longitude`, `theater`, `story_date`, `source_zh`, `source_en`, `battle_id`, `created_at`

**theater** 建议与现有一致：如 `north_africa`（会显示为非洲）、`pacific`、`europe`、`eastern_front`、`western_europe` 等，见 `Theater` 枚举。

### 2. 详情类 JSON（可选）

每个文件都是 **顶层一个数组**，例如：

```json
[
  { "id": "...", "battle_id": "...", "name_zh": "...", ... },
  ...
]
```

- **battle_units**：含 `battle_id`、`display_order` 等，见 `BattleUnit` 的 CodingKeys。
- **battle_unit_equipment**：含 `battle_unit_id`。
- **battle_images**：含 `battle_id`、`image_url`、`display_order`。
- **battle_timeline_events**：含 `battle_id`、`event_date`、`display_order`。
- **units**：单位主表；**unit_history_events**：含 `unit_id`、`event_date`。

具体字段名以各 Swift Model 的 `CodingKeys` 为准（均为 snake_case）。

## 三、获取 JSON 的方式

### 方式一：从项目内 SQL 本地生成（推荐，无需 Supabase）

项目里已有**全部数据的 SQL**，不需要从 Supabase 导出。只要本机装了 **Docker**，在项目根目录执行一条命令即可生成所有 JSON：

```bash
./scripts/sql_to_json_local.sh
```

脚本会用 Docker 启动临时 PostgreSQL，按推荐顺序执行全部 SQL，再导出到 `World War Archives/Data/`。详见 **`docs/从SQL生成JSON说明.md`**。

### 方式二：从已有 PostgreSQL 导出

若数据库已按 `docs/seed_execution_order.md` 执行完建表、迁移与种子 SQL（可以是本地库或 Supabase）：

1. 设置环境变量：`export DATABASE_URL="postgresql://用户:密码@主机:5432/数据库名"`
2. 安装依赖：`pip install -r scripts/requirements.txt`（或 `pip install psycopg2-binary`）
3. 运行：`python3 scripts/export_postgres_to_json.py`

脚本会生成 `World War Archives/Data/archives.json` 以及 `battle_units.json`、`battle_unit_equipment.json`、`battle_images.json`、`battle_timeline_events.json`、`tank_models.json`、`aircraft_models.json`、`units.json`、`unit_history_events.json`。字段名为 snake_case，UUID/日期已转为字符串格式。

### 方式三：从现有 Supabase 手动导出

若你本地或远程还有跑着的 Supabase，且表结构未改：

1. 用 Supabase Dashboard 的 Table Editor 每张表导出 CSV，再用脚本转成上面格式的 JSON；或  
2. 写一段小脚本（Node/Go/Python 等）调用 Supabase REST API，按表读取后写成：
   - 一张 `archives.json`（从 campaigns、battles、events、landmarks、soldier_stories 拼成五个数组，顶层键为 `campaigns`、`battles`、`events`、`landmarks`、`soldierStories`）
   - 若干详情 JSON（battle_units、battle_unit_equipment、battle_images、battle_timeline_events、tank_models、aircraft_models、units、unit_history_events）

导出时注意：
- 列名保持 snake_case，与上面字段表一致。
- UUID、日期格式按「二、JSON 格式要求」处理。

### 方式四：本机已装 PostgreSQL 时从 SQL 生成

你仓库里已有大量 `supabase_seed_*.sql`，内容多为 `INSERT` 或 `SELECT ... INTO`。

1. **在本地起一个临时 Postgres**，按 **`docs/seed_execution_order.md`** 中的顺序执行全部 SQL，然后用**方式二**的 Python 脚本从该库导出 JSON；或  
2. **写脚本解析 SQL**：  
   - 只处理简单的 `INSERT INTO table (col1, col2, ...) VALUES (...), (...)` 或 `SELECT ... INSERT INTO` 形式。  
   - 为每张表生成一个 JSON 数组文件，键名转为 snake_case，UUID/日期格式与「二」一致。  
   - 这种方式需要根据你实际 SQL 风格做解析，工作量相对大一些。

---

## 四、推荐流程（简要）

1. **从项目 SQL 生成 JSON**（推荐）：本机安装 Docker 后执行 `./scripts/sql_to_json_local.sh`，生成的 JSON 会写入 `World War Archives/Data/`。无需 Supabase。  
2. 在 Xcode 中确认 **Data** 已加入 **Copy Bundle Resources**。  
3. 运行 App，确认列表、地图、筛选与详情页正常。

---

## 五、当前占位文件

`World War Archives/Data/archives.json` 当前是一份**空数组占位**，结构如下，可直接被替换为完整数据而无需改代码：

```json
{
  "campaigns": [],
  "battles": [],
  "events": [],
  "landmarks": [],
  "soldierStories": []
}
```

替换时保持顶层键名不变，只替换各数组内容即可。
