## 二、部队履历（unit_id）缺失

部队履历依赖：`battle_units.unit_id` → `units` 表 → `unit_history_events`。

- **Second Battle of El Alamein**：`supabase_seed_units.sql` 末尾按名称批量回填 unit_id，约 34 个单位可显示履历。
- **Tunisia Campaign**：`supabase_seed_tunisia_campaign.sql` 末尾 + `supabase_seed_units_tunisia.sql` 提供 units，并回填 unit_id。
- **其余战役**：  
  - `seed_units` 的 UPDATE 未按 battle_id 过滤，理论上只要 `battle_units.name_zh/name_en` 与 `units` 表匹配就会回填。  
  - 但 `units` 表目前主要收录的是**第二次阿拉曼与突尼斯**相关番号（如第8集团军、第15装甲师、沙漠空军等）。  
  - 因此：**第一次阿拉曼、托布鲁克、加查拉、十字军、罗盘、战斧、克伦、达喀尔、火炬三场、凯塞林、加蓬、马达加斯加、比尔哈凯姆等**战役中的单位，若名称与 units 表不一致（如「西部沙漠部队」「中线特遣舰队」「奥兰师」「自由法国第1旅」），则 **unit_id 仍为 NULL，无部队履历**。

**缺失归纳**：  
- 除第二次阿拉曼、突尼斯外，多数战役的 battle_units **没有对应的 units 条目**，或名称不一致，导致 **部队履历缺失**。  
- 若需为这些战役显示履历，需要：在 `units` 中增加相应番号，并在 `unit_history_events` 中补充沿革，再在种子或补全脚本中按名称/显式映射回填 `battle_units.unit_id`。

   - 装备损失：顶层装备的 quantity_lost 可查史料补全。

3. **Operation Crusader / Compass / Beda Fomm / Sonnenblume / Medenine / Alam Halfa**  
   - 子单位：多数无 personnel_count 与伤亡 → 可按 OOB 与史料补估算人数或占比伤亡。  
   - 部队履历：需在 units 表增加北非早期/中期番号（如西部沙漠部队、第7装甲师、意大利第10集团军等），并做 unit_id 回填。

   - 盟军装备：可补舰艇、飞机型号与数量/损失。  
   - 盟军伤亡：completion 已有 167/340。

5. **Raid on Alexandria**  
   - 人员伤亡：可显式补 0 或「极少」，避免前端显示为空。

6. **Battle of Keren / Tunisia / Madagascar / Bir Hakeim**  
   - 逐单位核对：无 personnel_count 或伤亡的子单位补估算；无 quantity_lost 的装备行补 0 或史料值。  
   - 部队履历：对常用番号在 units + unit_history_events 中补录并回填 unit_id。

7. **第二次阿拉曼 / 突尼斯**  
   - 已有 unit_id 回填与较完整装备；仅需查漏：**无 unit_id 的单位**（名称与 units 表不一致的）补 units 或映射，**无 quantity_lost 的装备**补 0 或史料。

**（3）装备型号与 quantity_lost**

### 8.3 按优先级建议的补全顺序（第二轮）

1. **高优先级（影响展示）**  
   - 对**仍无 unit_id** 的常用番号补充 `units` + `unit_history_events`，并扩展 battle_units.unit_id 回填（按名称或显式映射）。  
   - 对**子单位仅有 personnel_count、无伤亡**的场次，按史料或占比补 personnel_killed/wounded/missing/captured（或显式 0）。

2. **中优先级（数据完整度）**  
   - 装备行 **quantity_lost 为 NULL** 的，补 0 或史料值，避免约束或前端显示异常。  
   - 克伦、马达加斯加、突尼斯等逐单位核对，补齐缺失人数/伤亡/装备损失。

3. **低优先级（可选）**  
   - 第二次阿拉曼、突尼斯中与 units 表名称不一致的单位，补 units 或映射使 unit_id 覆盖更全。  
   - 亚历山大港等「伤亡极少」的场次统一显式写 0，便于前端展示。

### 8.4 可选的 SQL 统计（在 Supabase 中验证）

在跑齐所有种子与补全脚本后，可在 Supabase SQL Editor 中执行以下统计，用于验证「仍缺失」的数量与分布。

```sql
-- 按战役统计：battle_units 数、无 unit_id 数、无 personnel_count 数、无伤亡数、无装备数、装备无 quantity_lost 数
SELECT
  b.name_en,
  COUNT(DISTINCT bu.id) AS units,
  COUNT(DISTINCT bu.id) FILTER (WHERE bu.unit_id IS NULL) AS no_unit_id,
  COUNT(DISTINCT bu.id) FILTER (WHERE bu.personnel_count IS NULL AND bu.parent_unit_id IS NOT NULL) AS child_no_count,
  COUNT(DISTINCT bu.id) FILTER (WHERE bu.personnel_killed IS NULL AND bu.personnel_wounded IS NULL AND bu.parent_unit_id IS NOT NULL) AS child_no_casualties,
  (SELECT COUNT(*) FROM battle_unit_equipment e JOIN battle_units u ON e.battle_unit_id = u.id WHERE u.battle_id = b.id AND e.quantity_lost IS NULL) AS equip_no_lost
FROM battles b
LEFT JOIN battle_units bu ON bu.battle_id = b.id
WHERE b.campaign_id IN (SELECT id FROM campaigns WHERE name_en IN ('North African Campaign', 'Madagascar Campaign'))
   OR b.name_en IN ('Battle of Dakar', 'Battle of Keren', 'Battle of Gabon', 'Tunisia Campaign')
GROUP BY b.id, b.name_en
ORDER BY b.name_en;
```

可根据上述结果在报告中更新「仍缺失」的具体战役与数量。
